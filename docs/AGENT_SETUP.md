# Agent Setup Runbook

This file is for an LLM agent setting up this repository for a human user.

The human should be able to say:

```text
Read docs/AGENT_SETUP.md and set this up globally.
```

Perform the setup. Keep the explanation short unless something fails.

## Goal

Prepare the global Copilot skill and its user-owned managed runtime so Excalidraw diagramming can be used from unrelated workspaces on this machine.

Project-local setup remains available only when the user explicitly wants the current workspace configured without a global skill install.

## Rules

- Use the explicit global installer; do not copy files manually.
- Do not require `npm install -g`, a system symlink, or administrator privileges for the default installation.
- Do not use `sudo` as the default response to npm `EACCES` errors.
- Do not overwrite unmanaged skill/runtime directories unless the user explicitly permits `--force`.
- Keep project-local `init` separate from global installation.
- Do not weaken quality/editability checks to make setup pass.
- Stop and report the smallest blocker if a required command is missing.

## Required checks

Run:

```text
node --version
npm --version
git --version
```

Minimums:

- Node.js `20.20+`
- npm `10+`
- Git available

## Global setup

From this repository checkout:

```text
npm install
npm run skill:install:global
npm run skill:doctor:global
```

Normal installation does not require `npm test`. Run the test suite when the user is developing/contributing or when setup is being used to validate a runtime change.

Confirm the managed directories exist:

```text
~/.copilot/skills/excalidraw-skill
~/.copilot/tools/excalidraw-skill
```

The skill directory must contain at least:

```text
SKILL.md
guides/
contracts/
diagram-types/
catalog/
docs/
.excalidraw-skill-install.json
```

The runtime directory must contain at least:

```text
bin/excalidraw-skill.mjs
src/
assets/
package.json
.excalidraw-skill-runtime.json
```

The skill marker must contain an absolute `runtimeEntry`. `doctor --global` must report `skillOk: true`, `runtimeOk: true`, and `ok: true`.

`cliOk` may be false. The optional terminal command is not required because the skill invokes the managed runtime directly.

After installation, reload VS Code or start a new Copilot Chat.

## Repository smoke check

When validating this checkout, run:

```text
npm run smoke
node ./bin/excalidraw-skill.mjs inspect examples/service-flow/payment-flow.visual-plan.excalidraw
node ./bin/excalidraw-skill.mjs editability-report examples/service-flow/payment-flow.visual-plan.excalidraw
node ./bin/excalidraw-skill.mjs validate examples/service-flow/payment-flow.visual-plan.excalidraw
node ./bin/excalidraw-skill.mjs quality-report examples/service-flow/payment-flow.visual-plan.excalidraw examples/service-flow/payment-flow.visual-plan.diagram.json
```

Important: inspect and validate the exact scene generated by `npm run smoke`: `examples/service-flow/payment-flow.visual-plan.excalidraw`.

## Managed runtime check from another workspace

The real installation boundary is an unrelated writable workspace, not this repository.

1. Read `runtimeEntry` from:

```text
~/.copilot/skills/excalidraw-skill/.excalidraw-skill-install.json
```

2. In a temporary or unrelated workspace, run:

```text
node <runtimeEntry> init
```

The `.opencode` and `.github/prompts` entrypoints must be created in that invoking workspace, not in the managed runtime directory.

3. If doing a deeper setup validation, create a small supported DiagramSpec in that workspace and run:

```text
node <runtimeEntry> build <spec.json>
node <runtimeEntry> inspect <output.excalidraw>
```

The managed runtime must work without relying on the repository as its current working directory.

## First user-facing dogfood test

Open a fresh Copilot Chat in an unrelated project and request:

```text
결제 승인 흐름을 Excalidraw 다이어그램으로 만들어줘.
사용 가능한 excalidraw-skill을 사용하고 diagrams/payment-approval.excalidraw에 저장해줘.
```

Expected behavior:

- Copilot discovers the global `excalidraw-skill` bundle.
- The skill reads `runtimeEntry` from its install marker.
- The runtime writes artifacts in the current project workspace.
- The requested `.excalidraw` file is generated.
- native editability and structural quality gates pass before success is reported.

Then test one real edit:

```text
diagrams/payment-approval.excalidraw에서 Payment Service 이름을
Payment Authorization Service로 바꿔줘. 나머지 수동 배치는 유지해줘.
```

The agent should inspect first and apply a local semantic patch rather than regenerate the full scene.

## VS Code Excalidraw extension

If the `code` command is available, check:

```text
code --list-extensions
```

If `pomdtr.excalidraw-editor` is missing, install it:

```text
code --install-extension pomdtr.excalidraw-editor
```

If `code` is unavailable, tell the user to install manually:

```text
Extension name: Excalidraw
Extension id: pomdtr.excalidraw-editor
```

## Optional PATH command

Only install the convenience command when the user explicitly wants `excalidraw-skill` in a terminal.

If `npm install -g .` reports `EACCES`, prefer a user-owned Node version manager or npm prefix. Do not automatically retry with `sudo`.

## Project-local setup

Use this only when the user wants entrypoints in the current project without global installation:

```text
npm install
npm run doctor
npm run init
```

Check:

```text
.opencode/commands/excalidraw.md
.github/prompts/excalidraw.prompt.md
```

`npm run init` does not install anything into `~/.copilot`.

## Update

After pulling a newer version:

```text
git pull
npm install
npm run skill:install:global
npm run skill:doctor:global
```

For contributors/runtime changes, also run the repository test/strict quality suite before considering the change verified.

## What success looks like

- global doctor reports `skillOk`, `runtimeOk`, and `ok` as true.
- the skill marker points to an absolute managed `runtimeEntry`.
- project-local `init` writes into the invoking workspace.
- `npm run smoke` and follow-up checks target `payment-flow.visual-plan.excalidraw`.
- the managed runtime can build from an unrelated writable workspace.
- a fresh Copilot Chat can create a supported `.excalidraw` scene and apply a local patch to it.
- the result opens in Excalidraw/VS Code when an editor is available.
