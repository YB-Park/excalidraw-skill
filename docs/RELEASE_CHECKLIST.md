# Release / Dogfood Checklist

Use this checklist before sharing a new version or declaring a new dogfood baseline.

## Package metadata

- `package.json` has the intended version.
- `bin/excalidraw-skill.mjs` is listed as the package binary.
- `files` includes `bin`, `src`, `skills`, entrypoints, docs, assets, and examples.
- Node.js and npm engine requirements match the installation docs.

## Repository regression

Run:

```text
npm test
npm run smoke
npm run smoke:system
npm run smoke:module
npm run evaluate:strict
```

The payment smoke follow-up checks must target:

```text
examples/service-flow/payment-flow.visual-plan.excalidraw
```

Do not inspect a different committed example as a substitute for the scene just generated by `npm run smoke`.

## CI quality gates

The main CI run should pass all of these without lowering thresholds or refreshing baselines just to get green:

- unit tests
- service/system/module smoke builds
- strict structural/perceptual/readability evaluation
- layout-candidate research check
- actual Excalidraw render regression for all runnable corpus cases
- accepted patch round-trip actual-render regression

## Installation boundary

Verify the managed global installation:

```text
npm run skill:install:global
npm run skill:doctor:global
```

`ok`, `skillOk`, and `runtimeOk` must be true.

A clean/unrelated writable workspace must be able to use the installed `runtimeEntry` for:

```text
init → build → inspect → patch → validate/editability/quality
```

The runtime must not depend on the repository being the current working directory.

## User-facing docs

Check that these agree with the current runtime:

- `README.md`
- `docs/GLOBAL_INSTALL.md`
- `docs/USAGE.md`
- `docs/AGENT_SETUP.md`
- `docs/PATCH_USAGE.md`
- `docs/SMOKE_TEST.md`

In particular:

- normal installation must not require contributor-only test commands
- current renderable profiles must be separated from contract-only profiles
- sequence must not be presented as renderable until its dedicated renderer exists
- patch docs must list the executable operation set
- examples must point at files that the documented command actually creates

## Agent entrypoints

Confirm these exist and route to the current contracts:

- `.opencode/commands/excalidraw.md`
- `.github/prompts/excalidraw.prompt.md`
- `skills/excalidraw-skill/SKILL.md`

## Visual review

Automated gates do not replace visual acceptance.

Before promoting a new baseline:

- open representative actual-render PNGs or `.excalidraw` scenes
- check route continuity, labels, whitespace, boundaries, and hierarchy
- manually review any new patch operation-class baseline before recording its signature

## Current scope

Contained dogfood currently targets:

- flow/service-flow/event-flow/data-flow supported profiles
- system `layered-system`
- module `component-view`
- local semantic edits of existing generated scenes

Do not expand sequence/deployment/context/internal-block scope as part of a release cleanup unless their dedicated renderer/quality corpus is intentionally being implemented.

## Ready for contained dogfood when

- CI is green with unchanged quality policy.
- the installed runtime passes the clean-workspace boundary.
- README/install/usage instructions match the commands currently shipped.
- a generated scene opens as native editable Excalidraw.
- at least one real create-and-edit workflow is visually reviewed end to end.
